Полная Спецификация Кликабельного Прототипа
Название: A/B Testing Tool for Retail Merchandising (v1.0)
1. Цель прототипа
Создать интерактивный кликабельный веб-прототип, который демонстрирует автоматизированный процесс проведения A/B-тестов в области мерчендайзинга.
Главная ценность: значительное сокращение времени на анализ магазинов, формирование групп и мониторинг результатов.
2. Целевая аудитория
Мерчендайзеры, планограммисты, категорийные менеджеры.
3. Ключевые ограничения (обязательны для реализации)

Один магазин — только в одном активном тесте.
Алгоритм подбора групп — полностью замокан.
Нет ролевой модели.
Нет подсказок значений по умолчанию.
Статусы активных тестов пересчитываются только при открытии главной страницы со списком тестов.
Тест завершается только после явного действия пользователя.

4. Поддерживаемые гипотезы (шаблоны)

Увеличение объёма продаж категории — метрика: % продаж категории от общего оборота.
Увеличение продаж на уровне магазина — метрика: общий объём продаж в рублях.
Неснижение продаж — метрика: изменение объёма продаж.


Уровень 2: Детальное описание экранов и поведения
Экран 1: Главная страница («Активные тесты» и «Завершённые тесты»)

Кнопка «Создать новый тест» размещается только в верхней панели приложения и не дублируется в контенте главной страницы.
Список активных тестов отображается в виде карточек.
Карточки тестов отображаются списком: в одном ряду должна быть только одна карточка, остальные карточки идут ниже.
В каждой карточке: название теста, категория, гипотеза, длительность, цветовой статус-индикатор.
При открытии главной страницы статусы активных тестов пересчитываются по моковым данным мониторинга и обновляются на карточках.
Клик по карточке активного теста → переход в дашборд теста.
Ниже активных тестов расположен раздел «Завершённые тесты».
Клик по карточке завершённого теста → переход в финальный отчёт.

Экран 2: Создание нового теста (самый важный экран)

Три основных элемента расположены компактно рядом (желательно в одной визуальной группе):
Выпадающий список «Категория товаров»
Выпадающий список «Гипотеза»
Поле «Целевой процент» (числовой input)

Динамическое поведение: в зависимости от выбранной гипотезы текст-подсказка рядом с полем меняется:
«Увеличение объёма продаж категории» → «Ожидаемый рост, %»
«Неснижение продаж» → «Максимально допустимое падение, %»

Кнопка «Продолжить к выбору магазинов» активна только после заполнения всех трёх полей.

Экран 3: Выбор тестовой и контрольной групп

Система автоматически показывает предложенные группы (мок).
Основной интерфейс — таблица со списком магазинов, занимающая правую широкую часть экрана (ориентировочно 60–70% ширины).
Слева располагается вспомогательная колонка: сверху блок фильтров, ниже компактная карта магазинов.
Фильтры по региону, формату магазина и объёму продаж собраны в одном блоке и расположены сверху вниз.
Таблица должна быть достаточно широкой, чтобы все колонки помещались без горизонтального скролла на обычной desktop-ширине прототипа.
При изменении статуса выбора магазина строки и колонки таблицы не должны визуально «прыгать».
Дополнительно — компактная карта в левой колонке.
Визуальное правило: занятые магазины — бледно-розовый фон, неактивны для выбора.
В таблице применяется сортировка: все незанятые магазины должны располагаться выше занятых.
При наведении на занятый магазин — тултип только с подсказкой «Участвует в тесте [Название теста]», отображается поверх строк и статусных плашек таблицы.
Плашка «Занят» является кликабельной: при наведении текст меняется на «Открыть тест», стиль плашки визуально акцентируется, клик открывает связанный тест в новой вкладке.
Магазины в таблице и на карте должны быть кликабельными.
Если предложенный магазин снят с выбора, на карте всё равно должно быть визуально понятно, в какую группу он был предложен: тестовую или контрольную.
Статусы «Предложен в тестовую» и «Предложен в контрольную» должны полностью помещаться в статусной плашке таблицы без обрезания текста.
Пользователь может менять состав групп: оставить не все предложенные магазины, снять часть выбранных объектов или добавить доступные магазины.
Ограничение «один магазин — только в одном активном тесте» сохраняется: занятые магазины недоступны для выбора.
Нельзя перейти дальше с неравными группами: тестовая и контрольная группы должны содержать одинаковое количество магазинов и минимум по одному магазину.
Кнопка «Использовать выбранные группы» активна только при равных группах → переход к следующему шагу.

Экран 4: Назначение изменений

Простая форма для выбора новой планограммы или планировки магазина из библиотеки для только тестовой группы.
Кнопка «Запустить тест».

Экран 5: Дашборд мониторинга активного теста

Верхний блок (единая визуальная группа):
Название теста + категория
Целевая метрика и текущий результат
Статус + рекомендация системы («Продолжить наблюдение», «Рекомендуется остановить тест», «Положительный результат» и т.д.), актуализированные при последнем открытии главной страницы
Длительность теста

Два графика рядом: Тестовая группа (цветной) vs Контрольная группа (серый).
Информационное уведомление (неблокирующее, в заголовке): «Внимание: в одной из групп были изменены планограммы/ассортимент. Это может повлиять на результаты.»
Кнопка «Завершить тест» (внизу).

Экран 6: Финальный отчёт

Структурированный отчёт по порядку:
Параметры теста (категория, гипотеза, целевой %)
Список магазинов в тестовой и контрольной группах
Процент похожести групп
Итоговый график
Итоговый замеренный результат
Кнопки действий: «Экспорт отчёта», «Создать новый тест»
